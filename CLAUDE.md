# Правила работы с проектом clinic_site

## Язык

- Всегда пиши на русском языке (общение, объяснения, комментарии)
- Тексты на сайте — на русском, без англицизмов
- Названия переменных и функций — на английском (camelCase)
- Названия CSS-классов — на английском, kebab-case (`hero-section`, `service-card`)

## Стек и архитектура

- **Только** чистый HTML5 + CSS3 + Vanilla JS
- **НЕ использовать** фреймворки (React, Vue, Next.js), пре-процессоры (SCSS, Tailwind), сборщики (webpack, vite)
- Один `index.html` со всеми секциями (одностраничник со скроллом)
- Стили в `css/style.css` + переменные в `css/variables.css`
- JS в `js/config.js` (данные клиники) + `js/main.js` (логика подстановки)
- Картинки в `img/`, иконки — SVG inline или через библиотеку `lucide`

## Конфиг — главная фишка проекта

- Все клиентские данные (название, телефон, адрес, врачи, услуги, цвета) — в **одном объекте `CLINIC` в `js/config.js`**
- HTML содержит только разметку, тексты подставляются JS из конфига при загрузке
- Любая правка под нового клиента — это правка ТОЛЬКО `js/config.js`
- НЕ хардкодить тексты/телефоны/адреса в HTML — всё через конфиг

## Дизайн

- Не трогай дизайн без спроса — всегда спрашивай перед изменением визуальной части
- Дизайн собираем по скриншотам референсного сайта, которые присылает Виктор
- Стиль: профессиональный, чистый, современный, медицинский (доверие)
- Цветовая схема — через CSS-переменные в `variables.css`, чтобы легко перекрашивать
- Стартовая палитра: бирюза `#1ABBC9` / тёмно-бирюзовый `#0A7480`, белый, серый текст
- Шрифт: Inter (Google Fonts) или системный

## Стиль работы

- Двигаемся последовательно, шаг за шагом — не летим вперёд
- **Один запрос = одна задача** (правило Ледовских от 22.04)
- Каждый шаг внутри этапа: объясни → спроси «Делаем?» → дождись «Да» → сделай → протестируй → доложи
- Между этапами: спроси подтверждение с описанием следующего шага
- Не усложняй — Виктор новичок, решения должны быть простыми и понятными
- Объясняй свои решения простым языком

## Проектная документация

- Перед началом работы прочитай `project.md` — описание проекта, ЦА, конфиг
- Перед началом задачи сверься с `PLAN.md` — актуальный план и статус этапов
- После завершения задачи — обнови `PLAN.md` (отметь чек-бокс)

## Тестирование

- **Обязательная мобильная проверка** (правило Ледовских) — каждый блок проверяется на телефоне через Telegram «Избранное» по live-ссылке Vercel
- Чек-лист мобильной проверки (8 пунктов, см. `training_ledovskikh_lifehacks_22apr2026.md`):
  открытие без зума / читаемый шрифт / кнопки 44+px / меню / формы / картинки в экране / скорость / клик по `tel:`
- Перед словами «готово» — обновить страницу в браузере + на телефоне

## Деплой и Vercel

- **Главная ссылка:** https://clinic-site-tan.vercel.app
- Деплой автоматический: каждый `git push` в `main` → Vercel пересобирает за 30-60 секунд
- НЕ нужно никаких build-шагов, никаких npm install — Vercel сам отдаёт статику
- Если деплой упал — проверить в Vercel Dashboard → Deployments → последний билд → логи

## Git

- Коммить каждую завершённую задачу отдельно
- **Формат коммита** (правило Виктора, `feedback_commit_format.md`):
  - Заголовок: `Этап N. Кратко что сделали`
  - Тело: разделы «Что добавили», «Что изменили», «Что сохранили», «Почему»
- Не коммить файлы с секретами (.env, ключи, токены)
- Перед коммитом проверь `git status` — не попало ли лишнее
- После коммита — сразу `git push` (чтобы Vercel обновил живую ссылку)

## Безопасность

- Никогда не хардкодь пароли, токены, ключи в код
- Используй `.env` для конфиденциальных данных, .env уже в `.gitignore`
- На этапе MVP формы — заглушки, реальная отправка после продажи

## Технические правила

- Код должен быть чистым и читаемым
- Не добавляй зависимости без согласования
- Не удаляй и не перемещай существующие файлы без спроса
- Не используй платные API/сервисы без согласования
- Предлагай самое простое решение из возможных

## Что НЕ делаем

- ❌ Бэкенд / API / база данных — только статика
- ❌ Реальная отправка форм (заглушка пока)
- ❌ Админка с сохранением — данные правим в `js/config.js` через Claude
- ❌ Telegram-бот — это Этап 8, после релевантного урока курса
- ❌ Многостраничность — только одностраничник со скроллом
- ❌ SEO сложнее базовых meta-тегов

# clinic_site — Универсальный демо-шаблон сайта для клиник

## Описание проекта

**clinic_site** — одностраничный сайт-витрина для медицинских учреждений (стоматологии, клиники, косметология, медцентры). Используется как **демо для холодных продаж**: Виктор показывает потенциальному клиенту персонализированный сайт «как будет выглядеть ваш сайт» — с его названием, телефоном, адресом — и предлагает купить.

Шаблон собирается на чистом HTML/CSS/JS, разворачивается на Vercel. Дизайн — копия с референсного сайта (платный шаблон, воспроизводится по скриншотам, не копируется код).

## Целевая аудитория

### Конечный покупатель шаблона
- Любые медицинские учреждения: стоматологии, многопрофильные клиники, косметология, медцентры.
- Владельцы малого/среднего бизнеса (без IT-отдела, не разбираются в коде).
- Уровень оснащённости: от «у нас вообще нет сайта» до «есть старый сайт 2010 года».

### Кто заходит на сайт (после продажи)
- Пациенты, которые ищут клинику в своём городе.
- Действие: позвонить, оставить заявку или написать в мессенджер.

## Ключевая проблема

**Виктор не может ничего показать в холодном outbound.** Слова «я делаю сайты для клиник» не работают — клиенту нужен **визуал** того, что он получит. Готовых демо нет.

Дополнительно: клиент должен увидеть **СВОЙ** сайт, а не абстрактный пример. Это резко повышает шанс продажи: вместо «я мог бы сделать вам такое» — «вот так будет выглядеть ваш сайт прямо сейчас».

## Уникальное торговое предложение (УТП)

**Персонализированное демо за 1-2 часа.** Виктор берёт открытые данные клиники (название, телефон, адрес из 2ГИС) → правит config.js → деплоит → отправляет ссылку. Клиент открывает и видит «свой» сайт.

**Позиционирование:** «Вот как будет выглядеть ваш сайт. Хотите такой?»

## Как это работает (механизм демо)

```
1. Виктор находит клинику-кандидата (TGStat, 2ГИС, Яндекс.Карты)
2. Собирает открытые данные: название, телефон, адрес, соцсети
3. Просит Claude обновить js/config.js под эти данные
4. git push → Vercel автодеплой → новая ссылка
5. Виктор отправляет ссылку клиенту в Telegram
6. Клиент открывает на телефоне → видит свой сайт → диалог о продаже
```

**Что ВИДИТ клиент:** название его клиники в шапке и Hero, его телефон везде, его адрес в подвале. Остальное (врачи, отзывы, акции) — типовые заглушки.

## Структура сайта (блоки)

Принцип: **«всё включено» — все блоки на сайте есть, клиент после покупки убирает ненужные**.

Список блоков (порядок сверху вниз) — финализируется по референсным скриншотам:

1. **Шапка** — логотип/название + меню + телефон + кнопка «Записаться»
2. **Hero** — заголовок про клинику + подзаголовок + CTA-кнопки + стат-блоки (опыт, пациенты, рейтинг)
3. **Преимущества** — 4-6 карточек с иконками
4. **Услуги/прайс** — карточки услуг с ценами
5. **Врачи** — фото + имя + должность + стаж (стоковые заглушки)
6. **Акции** — спецпредложения и скидки
7. **Галерея** — фото клиники
8. **Отзывы** — карточки с текстом и звёздами
9. **FAQ** — раскрывающиеся вопросы-ответы
10. **CTA-полоса** — финальный призыв «Запишитесь на консультацию»
11. **Подвал** — контакты, ссылки, соцсети, копирайт

Все блоки можно отключать через флаги в config.js (`sections.doctors: false` → блок не рендерится).

## Главное действие пациента (CTA)

На сайте 3 способа связи (одновременно):
- **Кликабельный телефон** (`tel:`)
- **Форма заявки** «Имя + телефон» — на этапе MVP это **заглушка** («Спасибо, заявка принята»). Реальная отправка — после продажи.
- **Кнопки мессенджеров** — ссылки на WhatsApp, Telegram (`https://wa.me/...`, `https://t.me/...`)

## Что в конфиге (js/config.js)

Один объект `CLINIC` со всеми переменными данными:

```js
const CLINIC = {
  // Брендинг
  name: "Клиника «Дентал»",
  tagline: "Красивая улыбка — наша профессия",
  logoUrl: "img/logo.svg",

  // Контакты
  phone: "+7 (495) 123-45-67",
  email: "info@dental.ru",
  address: "Москва, ул. Примерная, д. 1",
  workingHours: "Пн-Сб 9:00-21:00",

  // Соцсети и мессенджеры
  whatsapp: "+74951234567",
  telegram: "dental_clinic",
  instagram: "dental",
  vk: "dental",

  // Цвета бренда (применяются через CSS-переменные)
  brandColor: "#1ABBC9",
  brandColorDark: "#0A7480",

  // Какие блоки показывать
  sections: {
    advantages: true,
    services: true,
    doctors: true,
    promotions: true,
    gallery: true,
    reviews: true,
    faq: true
  },

  // Контент блоков (массивы)
  services: [/* ... */],
  doctors: [/* ... */],
  reviews: [/* ... */],
  promotions: [/* ... */],
  faq: [/* ... */]
};
```

При загрузке страницы JS подставит все значения из `CLINIC` в HTML. Чтобы перекрасить под нового клиента — меняешь только этот файл.

## Риски и контр-меры

| Риск | Контр-мера |
|------|------------|
| **«У меня уже есть сайт»** | Открыть старый сайт клиента на телефоне рядом с демо. Старые сайты часто кривые на мобильных — это видно сразу. |
| **«Это же Tilda, сам сделаю»** | Показать скорость: «За 2 часа готово под вас, без подписки». Tilda требует ежемесячной оплаты. |
| **«Нет SEO, не найдут в Google»** | Честно: сайт — витрина для рекламы и QR-кодов. SEO — отдельная услуга, обсудим после запуска. |
| **«Дорого»** | Развёрнутый перечень что включено: дизайн + адаптив + мессенджеры + хостинг на год + перекраска под бренд. |
| **Стоковые фото врачей** | На демо честно: «Это шаблон, ваши врачи и интерьер — после оплаты». На созвоне сразу обсуждаем замену. |
| **Бот пока не готов** | Не обещаем бота на старте. Когда доучимся — добавим как доп. опцию. |
| **Долгая персонализация** | Все правки — через один config.js. После 2-3 итераций процесс отлажен до 30 минут. |

## Метрика успеха (на этом этапе)

**Базовая (Этап 0-7):** Сайт открывается на десктопе и на телефоне, выглядит профессионально, не стыдно отправить клиенту.

**Бизнесовая (после Этапа 7):** Хотя бы 1 клиент в холодном outbound сказал «интересно, давайте обсуждать» после получения ссылки.

## Что НЕ входит в этот этап

- ❌ Бэкенд/API/база данных — только статика.
- ❌ Реальная отправка форм — заглушка `mailto:` или JS-сообщение.
- ❌ Админка — данные правим в config.js руками (через Claude).
- ❌ Множество вариантов дизайна — один шаблон, перекрашиваемый через переменные.
- ❌ SEO-оптимизация сложнее базовых meta-тегов.
- ❌ Telegram-бот — отдельная фаза (Этап 8) после релевантного урока курса.
- ❌ Многостраничность — только лендинг (одна страница со скроллом).
